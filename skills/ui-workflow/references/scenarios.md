# 5 Modern Frontend Scenarios — Routing & Decision Matrix

Classify the requested surface first. Never apply marketing-page decoration to a dense simulation console, and never ship a flat unstyled admin table as a product showcase.

| # | Scenario | Mode | Default Stack | Layout & Density | Typography & Palette Rule | Top Anti-Patterns to Block |
|---|---|---|---|---|---|---|
| 1 | **Data Workbench & Simulation Console** (trading/backtest monitor, policy simulator, experiment dashboard, BI cockpit) | `Operate` | Mode A (single-file HTML + CSS Vars + ECharts 5) or Mode B (Vite/Next + shadcn + ECharts 5) | Left/top compact parameter rail + primary ECharts canvas + scannable KPI strip + sortable comparison table | Neutral low-glare surface; `tabular-nums` mandatory everywhere; restrained semantic colors (baseline vs policy vs delta) | Hand-rolled Canvas 2D line charts; cramped parameter controls fighting charts; unaligned numbers; rainbow series |
| 2 | **B2B SaaS & Product App** (admin consoles, config managers, multi-step forms, CRUD workflows) | `Operate` | Mode B (`Vite` or `Next.js` + Tailwind + `shadcn/ui` via `folio-shadcn` MCP) | Persistent navigation shell, clear filter/action toolbar, 8px rhythm, crisp borders over heavy shadows | System/UI sans + monospace only for IDs/code/metrics; semantic status tokens (`success`/`warn`/`danger`) | Ad-hoc `<div>` modals/selects/sliders; missing Loading/Empty/Error/Disabled states; missing keyboard focus |
| 3 | **Marketing Landing Page & Showcase** (product launch, pricing, OSS home, portfolio) | `Persuade` / `Experience` | Mode B (Next.js/Astro/Vite + Tailwind) or custom semantic HTML/CSS | Generous vertical rhythm, one dominant focal composition per viewport, asymmetric or editorial grid | Strong display-to-body scale contrast, expressive accent disciplined to 10% area, purposeful motion | Default purple-blue gradients; 3 equal icon+title+text card rows; eyebrow kickers above every H2; identical scroll-fade everywhere |
| 4 | **Documentation, Editorial & Research Reports** (tech docs, interactive paper walkthroughs, changelogs) | `Read` | Static HTML / Markdown / Nextra / VitePress + ECharts 5 for interactive figures | `65ch–75ch` prose measure, sticky ToC sidebar on desktop, collapsible nav on mobile | High-contrast ink on paper/dark-slate ground, clear heading margin hierarchy (more above than below) | Full-bleed 1400px prose lines; overflowing wide tables or formulas on mobile; weak link/code contrast |
| 5 | **Existing UI Audit, Refine & Redesign** ("fix this ugly page", Figma handoff, pre-ship audit) | `Audit` / `Refine` / `Redesign` | Preserve incumbent stack for `Refine`; migrate only if explicitly asked | Run Phase 3 static check + Phase 4 rendered capture **before** editing | `Refine`: preserve existing palette/fonts/copy.<br>`Redesign`: author new `DESIGN.md` first | Blind editing without viewing rendered output; rewriting working business logic while fixing CSS; mixing old and new aesthetics |

## Mode Calibration Rule
- **`Operate` & `Read`**: Clarity, scanability, density discipline, and predictable native/Radix interactions outrank decorative flair.
- **`Persuade` & `Experience`**: Commit to a memorable visual point of view, strong typographic hierarchy, and one authored focal moment.
